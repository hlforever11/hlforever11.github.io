## 2026-10-08 更新（V17，访问基数1000）

网站与小程序分别以 **1000** 为起始基数，再累计各自的新增访问。1000 是指定起始值，不是查询得出的历史访问量。已有小程序新增记录保留，不与网站访问量相加。

本次更新修复了作者查询异常、全角与零宽字符解析、分段页码、英文姓名缩写、正式出版年与网络首发年混用、旧成功缓存等问题；增加期刊官网通用题录解析，避免仅为个别文章定向修改。期刊建议著录采用 GB/T 7714—2015 的作者—篇名—刊名—年—卷(期)—页码顺序，并保留提交序号。

您提交的六篇文章均有公开存在证据。前五篇有完整出版题录；吴爱红一篇的公开记录未完整提供卷号、页码，因此保留原著录并标注相关字段待复核。

更新现有小程序：

1. 解压 V17 完整项目，导入包含 `project.config.json` 的目录。
2. 右键 `cloudfunctions/userHistory`，执行“上传并部署：云端安装依赖”。本次计数调整只改了该云函数；若已部署过 V12 `verifyReference`，不必再次部署核验函数。若仍使用旧核验函数，则同时部署本包的 `verifyReference`。`extractDocument` 不需重新部署。
3. 测试 `verifyReference`，返回的 `build` 应为 `2026.10.08-12`。
4. 编译并预览，核验六篇文章；检查页面底部累计访问从1000基数递增。调用 `userHistory` 后，计数响应的 `build` 应为 `2026.10.08-visits-1000`、`legacyBase` 为 `1000`。

顶部“上传”只上传客户端版本，不会替代两个云函数的部署。

访问计数：

- 网站使用独立的新增访问计数记录，显示1000＋新增访问；小程序使用独立云数据库记录，两端不相加。
- 小程序每次启动计一次，重复请求同一启动标识不重复增加。数据库事务避免同时访问丢失计数。
- `legacyBase` 固定为1000，不再等待历史数据，也不读取旧的 `MINIPROGRAM_HISTORY_PV` 环境变量。以前为空值或其他数值的基数会自动统一为1000；`newVisits` 保留。
- 初次读取或断网时显示起始基数1000；有本机成功记录时显示最近一次值。失败会显示统计状态，不归零、不虚增、不冒充恢复了历史数据。
- 公开页脚统一为“累计访问 ×× 次”，不显示用户数或“新版累计访问”。

## 架构说明

没有使用 `web-view` 套壳。小程序前端只负责输入、文档选择和结果展示；跨域网页读取、开放数据库查询和 DOCX/PDF 解析均由微信云函数完成。

核验采用“搜索发现优先、结构化来源复核”的统一流程：

1. 同时检索百度学术、百度搜索、360 搜索和必应搜索，发现旧中文期刊、地方刊、会议论文和无 DOI 文献的公开题录；
2. 再由 DOI 注册元数据、Crossref、OpenAlex、Semantic Scholar、Open Library、期刊官网或机构库补强证据并纠正字段；
3. 真实性只依据篇名与作者、来源、永久标识等核心身份字段评分，年份、卷期页和文献类型差异单独作为著录准确性问题。

搜索结果必须满足“篇名高度一致，并且作者、来源、年份至少有一项支持”；近似篇名则至少需要两项支持，防止把同名或推荐结果误判为真实文献。多家搜索来源会合并为交叉证据。

用户选择 DOCX 或 PDF 后，小程序将其上传到 `temporary/` 云存储目录，取得临时地址并调用解析函数；函数返回后，小程序立即请求删除该临时文件。TXT 文件直接在用户设备读取。

首次调用 `userHistory` 时会使用云数据库集合：

- `reference_users`
- `verification_history`

数据只由云函数按当前微信 OpenID 读写，小程序前端不直接访问数据库。用户未主动启用历史记录时，不保存核验内容。

云函数使用的第三方来源包括百度学术、百度搜索、360 搜索、必应搜索、Crossref、OpenAlex、Semantic Scholar、DOI Citation Formatter，以及用户提交的原始网页。无需在小程序后台增加这些域名，因为请求由云函数发出，而不是由小程序客户端直接发出。

## 与网站共用核验服务

`verifyReference` 同时兼容小程序普通云函数调用和 HTTP 网关调用。让 GitHub Pages 网站使用同一套检索逻辑：

1. 先部署最新版 `verifyReference`；
2. 在 CloudBase 的“HTTP 访问服务/HTTP 网关”中，将该函数绑定到默认域名，触发路径填写 `/api/verify-reference`；
3. 开启对 `https://hlforever11.github.io` 的跨域访问；
4. 将最终的 `域名 + 触发路径` 写入网站 `reference-checker/config.js` 的 `window.WENZHENG_API_URL`。

HTTP 请求只接收 `{"reference":"单条参考文献"}`，不接收登录凭据；函数内仍执行 5000 字符长度限制。未配置网关或网关临时不可用时，网站会回退到浏览器端开放数据源，不会阻断基本功能。

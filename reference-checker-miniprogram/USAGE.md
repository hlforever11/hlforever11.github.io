# 统计口径与取数

## 数据字段

- total：新统计启用后，云端已接收的网站checked＋小程序checked。
- website/miniprogram.checked：取得终态结果的条次，含已确认、需修正、待复核、暂未证实。
- errors：服务异常的条次，单列，不计入checked。
- cacheHits：checked中复用缓存的条次，不另加到total。
- batches：至少上报过一个终态结果的核验批次，包含只有错误的批次。
- startedAt/updatedAt：云端首次收到统计/最后新增统计的时间（毫秒）。
- historicalTotal:null：未能确定旧版历史累计量，绝不把新起点0冒充历史总量。
- initialized:false：尚无已接收统计记录。

同一文献在新一轮再次核验，算新的核验条次；这不是去重后的作品数量。一个批次最多20条，使用随机批次ID＋位置去重；请求重试和丢失回包后的补报不重复增加。停止核验只记录已完成的部分，停止后的迟到结果不计。已接收统计不随清空业务历史而删除。

上报依赖网络和本机存储。离线会排队补报；若用户清理本机存储、长期使用旧客户端或统计服务不可达，可能漏报。计数准确反映已接收记录，不承诺覆盖所有历史交互。匿名客户端上报不是防恶意伪造的审计系统。

统计不保存题录内容、作者、网址、OpenID或IP。verification_usage集合保存累计文档totals-v1和每个随机批次的去重凭证；不要为凭证设置自动过期，否则长期离线补报可能重复计数。不要开放客户端直接读写集合。

## 查询

云开发控制台测试verifyReference，参数：
{"action":"usage.read"}

如电脑安装Node.js 18或以上，在项目根目录运行：
node tools/read-usage.mjs

读取当前仍保留、且早于新统计启用时间的小程序历史汇总：
node tools/read-usage.mjs --retained
或使用参数{"action":"usage.retainedHistory"}。

retainedHistory.referenceSlots仅汇总当前保留的自愿历史中的referenceCount，可能含错误结果。该数据不是全体用户全量历史，也不与新实测量自动相加。业务历史被删除或50次保留上限覆盖的部分无法由此恢复。

统计查询不进行文献核验，不写统计；旧云函数返回的“没有收到参考文献”不会被当作有效统计。

## 历史情景估算（不写入实测数据库）

依据用户2026年10月8日反馈的小程序平台用户数1041：
- 假设每位用户累计完成1批、每批5条：1041×1×5＝5205条次，可粗略记为约5000。
- 假设每位用户累计核验3—10条：对应3123—10410条次。
这是显式假设的情景估算，不是抽样推断、置信区间或实测。1041用户数本次未从后台复核；未外推10月8日之后的增长，也没有加入缺少基准的网站历史，因此不能声称是截至11月4日两端历史总量。
1000/900人为访问基数、500篇/1300条评测样本都不参与此估算。

## 架构说明

没有使用 `web-view` 套壳。小程序前端只负责输入、文档选择和结果展示；跨域网页读取、开放数据库查询和 DOCX/PDF 解析均由微信云函数完成。

核验采用“搜索发现优先、结构化来源复核”的统一流程：

1. 同时检索百度学术、百度搜索、360 搜索和必应搜索，发现旧中文期刊、地方刊、会议论文和无 DOI 文献的公开题录；
2. 再由 DOI 注册元数据、Crossref、OpenAlex、Semantic Scholar、Open Library、期刊官网或机构库补强证据并纠正字段；
3. 真实性只依据篇名与作者、来源、永久标识等核心身份字段评分，年份、卷期页和文献类型差异单独作为著录准确性问题。

搜索结果必须满足“篇名高度一致，并且作者、来源、年份至少有一项支持”；近似篇名则至少需要两项支持，防止把同名或推荐结果误判为真实文献。多家搜索来源会合并为交叉证据。

用户选择 DOCX 或 PDF 后，小程序将其上传到 `temporary/` 云存储目录，取得临时地址并调用解析函数；函数返回后，小程序立即请求删除该临时文件。TXT 文件直接在用户设备读取。

## 与网站共用核验服务

`verifyReference` 同时兼容小程序普通云函数调用和 HTTP 网关调用。让 GitHub Pages 网站使用同一套检索逻辑：

1. 先部署最新版 `verifyReference`；
2. 在 CloudBase 的“HTTP 访问服务/HTTP 网关”中，将该函数绑定到默认域名，触发路径填写 `/api/verify-reference`；
3. 开启对 `https://hlforever11.github.io` 的跨域访问；
4. 将最终的 `域名 + 触发路径` 写入网站 `reference-checker/config.js` 的 `window.WENZHENG_API_URL`。

HTTP 请求只接收 `{"reference":"单条参考文献"}`，不接收登录凭据；函数内仍执行 5000 字符长度限制。未配置网关或网关临时不可用时，网站会回退到浏览器端开放数据源，不会阻断基本功能。
